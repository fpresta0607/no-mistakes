**Home-Path Redaction in Published PR Content (security)**

- `internal/safepath` is the one owner of home-directory redaction, the path analogue of `internal/safeurl`. `RedactText` rewrites the process's own home plus `/home/<user>`, `/Users/<user>`, and `C:\Users\<user>`, with their drive-mount (`/c/...`, `/cygdrive/c/...`, `/mnt/c/...`) and `file:///C:/...` spellings, to `~`, unconditionally and for every occurrence. Add new shapes there rather than scrubbing paths at a call site. Candidate resolution must stay free of `filepath.IsAbs`/`VolumeName` and of any reliance on `filepath.Clean`'s separator normalisation: those answer for the build platform, and on Windows `IsAbs` discards the POSIX-rooted `HOME` that Git Bash, MSYS2, and Cygwin set - silently disabling redaction instead of failing. Regression: `TestUsableHomeCandidate_AcceptsBothPlatformSpellings`, `TestHomeCandidates_AreSeparatorSpellingIndependent`.
- `redactPRContent` in `pr.go` owns the publication redaction boundary. It calls `safepath.RedactPublished`, the one composition both boundaries share: `safepath.RedactRunEvidence` (the run's evidence directory, to `{run-evidence}`) and `safepath.RedactWorktrees` (the run worktree `sctx.WorkDir`, then any run worktree under `nmWorktreesRoot()`) before `safepath.RedactText`. Add a new path rewrite inside `RedactPublished`, never at one boundary: the evidence branch missed `{run-evidence}` for as long as each boundary composed the redactors itself (issue #97). The order is not load-bearing: `publishedSpellings` also matches each root's `~` form, which a path written from `~` needs anyway. `PRStep.buildPRContent` uses it for ordinary drafts; template creation and live author-preserving updates use it through `composeOwnedPRContent` before stamping their byte-integrity guard. Every source that can reach a PR body - agent prose, extracted intent, findings, fix summaries, step errors, and agent-written artifact content - is covered there, so a new rendering path cannot reintroduce the leak. Ordinary drafts redact after length caps (the placeholder never grows a path, and `replaceDirectory` also matches a path a cap stopped inside the run ID, so no cap needs redaction of its own); template composition redacts before its integrity guard and fail-closed size check. `pr_ownership.go` owns that marked-appendix contract: never feed live author text through heading-based stripping/clamping, and keep `rebindOwnedPRAttestation` in the pre-push restamp path so its integrity guard remains valid. Regressions: `pr_template_test.go`, `pr_ownership_test.go`.
- The `artifacts[].path` description in `testFindingsSchema` (`common.go`) must not solicit absolute paths, and must not forbid them either. The renderer's allowlist is the worktree or the run's evidence directory and a path under neither is dropped, while the evidence directory defaults under the operator's home - so soliciting more just re-supplies what the boundary has to strip, and a blanket "never report a home directory path" clause makes an obedient agent drop its own evidence. Publication safety is the `pr.go` boundary's job; the schema only stops soliciting paths from elsewhere on the machine. Regressions: `TestTestFindingsSchema_DoesNotSolicitAbsolutePaths`, `TestTestFindingsSchema_KeepsEvidenceDirectoryPathsReportable`.
- The opt-in evidence branch (`test.evidence.store_in_repo`) is the second boundary: `evidence.Publish` withholds any file that `agent.CarriesCapturedPrompt` recognizes, whatever its encoding, and runs the remaining clean UTF-8 text through `safepath.RedactPublished` (`hashEvidenceFile`, owned by the `test-evidence-storage` skill). One other public surface deliberately does NOT share this rendering and is not covered: agent-authored commit subjects (`commitAgentFixes` -> `Commit.RenderFixMessage`) and their trailers (`withCommitTrailers` -> `Commit.RenderTrailers`, whose agent and model values are reduced to one safe token), which reach the remote through Push. Keep the `internal/safepath` package doc honest about that scope.
- The PR body must contain exactly ONE live pipeline-attestation marker, the run's own. `require-no-mistakes` (`.github/actions/require-no-mistakes/verify.py`) binds the FIRST marker in the RAW body to the PR head, so a foreign copy placed earlier fails a PR the pipeline did produce - and a code fence is no defense, because that scan is raw text. Step agents embed foreign markers routinely, by capturing a generated PR body as evidence.
- A CI repair that publishes a new head rewrites only that live marker's `head_sha` in the current PR body (`restampPublishedAttestation`) and does not send a title. It never inserts a marker that was not already there. Hosts without a PR content reader skip the restamp instead of failing the push. Regressions: `TestCIStep_PublishRepairRebindsAttestationAcrossRepairPushes`, `TestCIStep_PublishRepairDoesNotMintAttestation`, `TestCIStep_PublishRepairSkipsRestampWithoutReader`, `TestRestampPRAttestation_PreservesContentEditedWhilePreparingRewrite`, `TestUpdatePROmitsTitleWhenEmpty`.
- `repository_overrides.<url>.pr.update_text` is `keep` or `regenerate` (default, also the absent key). `keep` is machine-local only. On create it uses the ordinary drafter and stores the narrative above an owned appendix (`publishKeptDraft`). On an existing PR it reuses the template preservation path: the title is omitted unless `pr.title_format` is set, the bytes before the appendix stay, and the appendix or `minimal` risk line plus the attestation are rebuilt for the current head. An unowned attestation still fails closed. `regenerate` stays on the ordinary rewrite. Regressions: `TestPRUpdateTextKeepOnUpdate`, `TestPRUpdateTextKeepOnCreate`, `TestPRUpdateTextRegenerateRewrites`, `TestPRUpdateTextKeepRefusesUnownedAttestation`, `TestRepositoryPRUpdateText`.
- A caller-supplied PR description (`axi run --pr-body-file`, `runs.pr_body`) is author text, published on create only through `buildSuppliedPRContent` as the narrative above an owned appendix. It never goes through `stripGeneratedSections` or a drafting turn; it does go through `neutralizeAttestationMarkers` and the `composeOwnedPRContent` redaction boundary. `steps.ValidateRunPRBody` (CLI and daemon) refuses reserved markers, controls, and bidi overrides before it is stored; the PR step never applies it to an existing PR. Regressions: `TestPRSuppliedTextCreatesOwnedBody`, `TestPRSuppliedTextIsNotAppliedToAnExistingPR`, `TestPRStep_SuppliedBodyIsRedactedBeforePublishing`.
- Neutralize at the assembly choke point (`appendGeneratedSectionsToCleanBodyWithinLimit` plus the two intent paths), never per render path. `pipelineMD` alone carries the real marker and is left intact; `BuildPipelineSummaryFor` neutralizes its own step-detail blocks, which quote agent text. A first attempt put this in `escapePipelineFoldMarkers` - per-render-path - and shipped three live foreign markers to #831 anyway. Regressions: `TestPRStep_ForeignAttestationsInEveryComponentDoNotShadowTheRealOne` (all components at once), plus the per-component guards in `pr_test.go`.
- `redactPRContent` also runs `neutralizePRControls` (`pr_controls.go`): published bytes must be a fixed point of `gh pr view --json`, whose sanitizer rewrites C0/C1 controls and the literal text `\u00XX` of them to caret notation, or the post-create body check and the appendix digest fail with a false "edited" refusal (#1435, #1454). `composeOwnedPRContent` neutralizes the appendix BEFORE `escapePRAppendixMarkers` so removing a byte cannot splice a marker together after the escape ran. `parsePROwnedBody` still accepts an appendix whose digest matches only after `restoreCaretControls` (PRs stamped by older versions). `internal/pipeline/fakecli/ghsanitize` is the shared port of that sanitizer; do not hand-write another. Regressions: `internal/pipeline/steps/pr_controls_test.go`.
- Regressions: `internal/safepath/redact_test.go`, `internal/pipeline/steps/pr_homepath_test.go`.

**Evidence Files Stay Out of the PR Body (issue #57)**

- A file in the run's evidence directory is a raw capture: a Test agent's product-level artifact can hold the prompts a stub agent received, the `agent.ExecutionContextPromptSection` block, and scratch paths under `<evidence>/test-scratch`. Redaction only trims path prefixes, so it is not a publication decision and must not be treated as one. `renderPrivateEvidenceReference` is the only rendering of such a file: label plus `sha256:` digest (or a truthful "unreadable" note), in both `test.evidence.compact` modes and on every provider, and never its bytes or path. Do not restore inline previews, and do not gate them on `compact`, which a pushed branch can set.
- `artifact.content` is the deliberate public channel: agent-written, curated, and published as it stands. The Test prompt and `testFindingsSchema` say so, and `appendTestingArtifacts` replaces content that `agent.CarriesCapturedPrompt` recognizes with `withheldArtifactContent`, so a pasted prompt leaves a visible notice rather than the prompt. That check matches any eight-word run of a fixed line of either block, derived from the renderers so `internal/agent` stays the one owner of the wording. It is a backstop, never a reason to let file bytes back in.
- The opt-in evidence branch and media uploads remain the only ways a file leaves the machine, and the opt-in is not a license to publish what the PR body withholds: the evidence branch makes the same `agent.CarriesCapturedPrompt` decision for every file (issue #97, `test-evidence-storage` skill). The GitLab `## Evidence` section names files relative to the run directory, so it carries no run ID.
- Regressions: `internal/pipeline/steps/pr_evidence_privacy_test.go`, `TestPROwnershipRedactsTheRunEvidenceDirectory`, `TestRedactRunEvidence_RewritesEverySpellingOfTheDirectory`, `TestRedactors_MatchEveryDriveSpelling`, `TestRedactors_MatchTheHomeRelativeSpelling`, `TestRedactors_RewriteAPathCutInsideTheRunID`, `TestRedactors_RewriteADirectoryEndingASentence`, `TestCarriesCapturedPrompt`, `TestCarriesCapturedPrompt_RecognizesEveryLineOfBothBlocks`.

**Pre-Push Pipeline Attestation**

- Broad Test approvals publish `StepResult.TestOverrideReason()` as the separate `steps[].test_exception` field and a marked human section; `override_reason` and `allow_test_command_override` remain command-only.
  `axi refresh-pr --run` adds only this metadata to a settled latest run's existing, unchanged open PR, through guarded daemon ingress and the branch lock, without replaying validation or changing the run.
  Refuse active executors, stale publication identity, unreadable or ambiguous markers, edited exception text, and uncertain writes; preserve owned-appendix integrity and author bytes.
  Owners: `pr_test_exception.go`, `pr_refresh.go`, `daemon/pr_refresh.go`, `cli/axi_refresh_pr.go`; regressions: `TestRefreshPublishedPR`, `TestPRRefreshRunIdentity`, `TestHandleRefreshPR`, `TestAxiRefreshPR`.

- `publishRunHead` must write an existing PR attestation for the proposed head before pushing it on every supported provider with raw content reads. `docs/src/content/docs/reference/repo-config.md` (`pr.template`) owns provider-specific ownership/budget and visible Bitbucket metadata caveats. The protocol has single-publisher scope because the daemon enforces one active run per repository branch; do not add cross-publisher coordination without a separate requirement. Detailed behavior is owned by `docs/src/content/docs/reference/pipeline-steps.md`; local rationale lives in `attestHeadBeforePush` and `publishRunHead`. Regressions: `TestPushStep_AttestsHeadBeforePush`, `TestPushStep_AttestationWriteFailureAbortsBeforePush`, `TestPushStep_UnavailableSCMLeavesStaleAttestationFailingClosed`, `TestPushStep_PushFailureAfterAttestationLeavesBodyAhead`, and `TestCIStep_PublishRepairRebindsAttestationAcrossRepairPushes`.
